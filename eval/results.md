# v0.1 results — effectiveness unproven

The preselected T1r1 main comparison did not provide a convincing visible
contrast to the owner. After watching the labeled opening, the owner said
“加 Skill 前后没什么区别，对比不明显”. The sample was rejected for the
introductory video. This is involved, labels-known production feedback, not
an independent blind vote or a conclusion that the Skill never helps.

## Completed engineering evidence

- Formal batch: 12/12 tasks, with 24/24 initial/final versions compiled and rendered.
- Six pairs: common visible prompt hashes and narration inputs matched; final
  decoded narration hashes matched within every pair.
- Actual browser check: all 12 finals played to the end at normal speed and
  sought to 0, 5 and 9.5 seconds. This does not establish comprehension.
- Local deterministic unit checks: 16 passed. Shared starter and fixture checks
  passed; public clone/Skill-format smoke passed. No remote CI claim is made.
- Offline review form: autosave/reload, JSON export and 1280/390 layouts checked
  with TEST_ONLY records. No test record is a human rating.
- Initial xhigh pilot: aborted on transport timeouts, excluded from quality counts.
  Medium pilot: two tasks/four renders passed infrastructure checks. Its temporary
  local-only narration is excluded from formal counts and public media.

[Per-task states, actual call time and token usage](results.json). Call time
includes CLI overhead and excludes compilation/rendering. Dollar billing is
unknown. No speed, savings or quality improvement claim follows from this sample.

## Limits and production decision

Independent human blind ratings: 0 collected. The 10-second tasks do not establish
an advantage for a 60-second multi-scene video. Both arms already produced object
relationships and state changes; changes in layout alone do not prove an effect.

Both arms used the same visible technical summary, not the full official Remotion
Skill package. The discovery-isolation CLI flag is experimental; opaque host
system context was not captured. One repeated A initial call reported 20,593 input
tokens versus 25,000 for its identical visible prompt in the other repetition.
Visible-input hashes are verified; identical hidden context cannot be proven.
Model review received three stills, not complete video playback.

The introduction's full rough cut has not started. The rejected 8-second opening
is retained locally for traceability, not promoted as a successful before/after.
A local v0.2 candidate adds connected scenes, persistent objects and purposeful
framing. Its separate 30-second diagnostic pilot is post hoc and must not be
mixed into this first batch or used as confirmatory proof.

## Inputs and provenance

Formal narration came from the owner's existing project workflow and account-owned
voice, with owner-authorized public experimental distribution. Public inputs
contain normalized audio, text/timings and hashes; credentials, account/voice
identifiers, provider sidecars and raw execution logs are excluded.

[Source provenance](source-provenance.json) maps an unpublished cache-cleanup amend
to public method commit `962135a`; all frozen model/render input hashes stayed
unchanged. MIT covers original source code, not the narration voice or third-party
tools. Use your own cleared narration for unrelated projects.
