# Resource-backed Skill pilot — freeze before generation

Objective: a genuine no-Skill / with-Skill comparison for an introductory video.
No directed reference clip can substitute for either experimental output.

The revised product includes scene/camera instructions and reusable source code,
not only a longer prompt. Test that complete package honestly: B receives the
Skill and a portable `scene-world.tsx` resource; A receives the shared technical
baseline. Both otherwise receive the identical T2 data-comparison brief, narration,
300-frame starter, dependencies, model and budget. The teaching data (30s versus
10s) is video content, not a measurement of the Skill's production speed.

T2 is a transfer task: the directed reference was a queue, while this case compares
three task durations. The generic resource contains no task-specific data, camera
timeline, completed video or final composition. The generation model must design
the actual scene. Mount the resource only in B, disclose this as part of the Skill
treatment, and save its exact bytes/hash. Do not claim a pure-text-only comparison.

One pair, order AB, gpt-6.1-sol/medium. One initial generation and one equal review
per arm; 600s per model call. No model tools. Review gets 0,5,9.5-second stills and
the same diagnostics/instructions. No author edits to generated Scene source.
Freeze all inputs, preserve ordinary/failed outputs and actual usage. Do not
replace an unsuccessful result with the directed reference or cherry-pick retries.

This is a post-hoc pilot after v0.1/v0.2, not a new preregistered formal batch.
Preselect this pair as its showcase before generation; assess factual accuracy,
phone readability, actual camera/scene changes and the owner's visual judgment.
If there is still no convincing gain, do not cut a promotional success story.
Independent blind ratings and generalization remain separate follow-up work.

## Following revision: explicit scene-led default

The first resource-backed pair still selected a fixed flat chart and did not
import the optional resource. Preserve that v0.3 pair and its exact input snapshot.
The next revision clarifies the product's default visual style: invocation opts
into connected scenes and meaningful close-to-wide framing, while explicit user
requests for fixed/static views still take precedence. Data accuracy and the
common comparison scale remain mandatory. This is a visual-style capability,
not a universal claim that moving cameras improve comprehension.

Regenerate both A and B once on the same T2 task and common budget. Keep the next
pair regardless of outcome. Stop this development round after that pair; no more
retries to seek a preferred winner. A promotional claim requires an actual useful
observable difference, not merely more motion or a manually authored substitute.

## v0.5: scene preset after explicit owner rejection

The owner judged the v0.4 camera-only difference insufficient. That pair remains
unchanged and does not enter the promotional episode. This is a product change,
not another draw from the same frozen v0.4 treatment.

Add a reusable spatial comparison preset with object assembly, a common metric
and shared measuring pass. It contains generic layout and behavior but no T2
values, task labels, narration, camera shots or completed composition. The model
must configure these from the original brief. Disclose that the Skill now includes
a scene preset; do not claim the outcome comes from prompt instructions alone.

Keep exactly the same T2 question, common prompt, audio, model and per-arm budget.
Run both arms afresh once (AB), preserving both initial and review outputs. No
manual changes to generated Scene source, no rerun to seek a stronger result and
no directed reference substituted. The sole new treatment is the revised package.
Inspect correct common scale and phone readability as well as visible contrast.
This development case is not independent transfer or human blind-evaluation proof.
