# 可执行的场景与镜头配方

按当前内容选择配方，再填写主体、状态和镜头位置。不是把几张完整海报排成一条长画布。

## 局部事实 → 关系揭示 → 全貌确认

开始时让当前动作或证据占据主要画面，背景关系先在画外。跟随同一个对象，或拉远把它与上下游的关系露出来。结尾保留原对象和关系，扩大取景确认结果。

近景要真正隔离主体，例如主对象约占可用画面的半宽至三分之二；全景则要看清相互关系。按实际图形尺寸计算取景，不把 1.00→0.96 的微缩当作从近景到全景。若主体宽 200 世界单位，在 1080 画布中近景 zoom≈3 才有约 600 像素；整体宽 1600 时，全景 zoom≈0.55。数值是计算示例，不要脱离当前图形照搬。

## 共同尺度的差异揭示

适用于时间、数量、前后差异。先让观众看清共同单位或一个具体构成，再揭示整体差异，最后在同一观察位置和同一尺度上落定比较。

- 先布局真实数据、共同零点、单位和标签；镜头位置由这些对象的位置计算。
- 局部构成可以靠近看；完整比较时把双方一起纳入画面。镜头缩放必须同时作用于双方，不能单独放大某一组制造优势。
- 分段长度或高度与数据成比例。使用立体体块时，正交投影可以保留平行方向上的比例；不要用透视深度、不同基面或不同取景偷换数据。
- 比较成立后，保留数据主体，让标尺、差值或对齐动作完成论点；不用一个独立的“结论页”取代证据。
- 近景、揭示和最终比较各留出与口播相符的阅读时间。文字难读时调整构图或取景，不以运镜牺牲准确性。

## 同一空间内改变机制

适用于流程与瓶颈。先近看一个操作，再揭示对象怎样积累；在原空间改变限制条件，跟住同一批对象，最后看结果如何传回整体。先写出对象身份、路径和状态表，避免转场中消失、重复或凭空变数。

## Remotion 资源

使用 [scene-world.tsx](../assets/scene-world.tsx) 中的 `CameraGroup`、`WorldBlock` 和 `project` 来搭建同一空间与多种取景。它们只依赖 React 和 Remotion；不带字体、音乐、私有组件或任何已做好的实验视频。

`WorldBlock` 是可变尺寸的三面体块；`project([x,y,z])` 把世界坐标映射到 SVG 坐标；`CameraGroup` 使用递增帧号的 `{frame,x,y,zoom}` 控制取景。`x/y` 是投影后的视野中心。将必要标签置于主体旁，或在 SVG 外保留稳定字幕。根据内容和风格选择平面或体块表达，不为了用资源而堆立体效果。

普通项目中将资源复制到项目源码后导入。纯文本生成评测若明确预装了 `src/scene-world.tsx`，直接导入该模块；不能依赖评测没有提供的文件。不要直接交付示例内容，应使用当前口播、数据和对象重新布置场景。
